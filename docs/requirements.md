# LocalChipAdvisor 首版需求基线

状态：已确认  
范围：MPS Buck 辅助选型原型  
数据阶段：先 20–30 个型号，通过验收后扩展到约 200 个型号

## 1. 产品目标

系统接收用户用自然语言描述的工业设备降压需求，提取并归一化参数，追问缺失或歧义信息，经用户确认后执行确定性筛选。信息不足时只能给出初步候选；信息充分时输出最多三个正式推荐，并展示参数满足矩阵、排序理由、风险、近似候选、待核实候选和可定位证据。

RAG 只承担证据检索和解释，不独自承担数值合规判断。推荐核心由结构化产品数据、确定性规则和排序逻辑组成。

## 2. 首批器件范围

- 品牌：Monolithic Power Systems（MPS）。
- 品类：非隔离、集成功率 MOSFET 的同步 Buck 转换器。
- 场景：约 12 V / 24 V 工业输入、1–5 A 输出。
- 首批：20–30 个型号；验收后扩展到约 200 个型号。
- 暂不纳入：外置 MOSFET 控制器、电源模块、多相控制器、隔离电源、车规专用型号、超大电流或服务器电源方案。
- 首版不依据价格、库存或交期推荐；生命周期状态必须携带数据日期。

## 3. 需求输入

### 3.1 正式推荐的最低输入门槛

- `vin_min`、`vin_nominal`、`vin_max`。
- 浪涌电压及持续时间；未知时明确记录为未知。
- `vout_target`、`vout_tolerance`。
- `iout_continuous`、`iout_peak`、`peak_duration`。
- 最高环境温度。
- 散热条件或可用 PCB 散热条件。

### 3.2 可选硬约束

- 封装与尺寸上限。
- 固定或可调输出。
- 开关频率范围。
- 强制 PWM、轻载模式等工作模式。
- 必需的保护、Power Good、同步功能。
- 静态电流上限。
- EMI 或噪声要求。

### 3.3 软偏好

- 效率。
- 温升余量。
- 方案面积。
- 外围器件数量。
- 设计复杂度。

系统保留用户原始表述并统一单位。未知值保持未知，不自动补默认值。自然语言解析结果必须先显示为需求确认卡；用户确认后才允许正式筛选。

## 4. 产品数据与证据

产品数据至少覆盖：

- 身份：基础型号、完整订货号、系列、产品状态、数据版本。
- 电气：推荐输入范围、绝对最大输入、输出范围、连续/峰值电流。
- 性能：开关频率、静态电流、关断电流、反馈基准、精度。
- 热与封装：结温范围、热阻、封装、尺寸、散热焊盘。
- 功能：软启动、使能、Power Good、同步整流、轻载模式。
- 保护：OCP、OVP、UVLO、OTP、短路保护及适用条件。

每个关键字段必须绑定证据对象：原始文件哈希、文件版本、页码/章节/表格、原文片段。LLM 只能引用程序提供的证据编号，不能自行生成文件名、页码或来源。

资料按以下权威顺序处理冲突：

1. 最新版官方 Errata / 勘误。
2. 最新版官方 Datasheet。
3. MPS 官方产品页面。
4. MPS Selection Guide。
5. MPS Application Note / Design Guide。
6. 经人工确认的内部规则。
7. 其他资料仅供参考。

原始资料仅从 MPS 官方公开来源半自动收集，由用户最终确认。自动抽取的数据进入草稿库，人工核对关键字段和证据后才能发布到正式推荐库。

## 5. 规则与状态

硬过滤只使用适用测试条件下明确保证的 Min/Max 或额定范围。Typical 值和典型曲线只能参与排序与风险说明，不能证明硬约束满足。

官方推荐工作范围决定基础合格；项目级降额规则在人工确认后才能影响优选或额外淘汰。Absolute Maximum Ratings 不作为正常设计目标。

硬约束采用三态：

- `PASS`：有可定位、已审核证据证明满足。
- `FAIL`：有证据证明不满足。
- `UNKNOWN`：资料缺失、条件不匹配、来源冲突或尚未人工确认。

只有所有必需硬约束均为 `PASS` 的型号可以进入正式 Top 3。包含 `FAIL` 的型号只能进入近似候选并显示违反项与风险；包含 `UNKNOWN` 的型号只能进入待核实候选并列出缺失证据。

## 6. 排序优先级

1. 电气条件完全满足。
2. 输入电压与输出电流具有合理安全余量。
3. 温度与散热风险更低。
4. 效率更高。
5. 保护功能更完整。
6. 封装和外围电路更简单。
7. 成本、库存和交期；首版不实现。

满足全部硬约束的型号不足三个时不补齐。系统不能把近似候选混入正式推荐。

## 7. 固定输出契约

1. 需求确认：原始需求、归一化参数、未限定条件。
2. 合格推荐：最多 Top 3，不强行凑数。
3. 参数满足矩阵：状态、要求值、器件值、余量、证据。
4. 排名理由：明确区分保证参数与 Typical 表现。
5. 工程风险：热、浪涌、降额、EMI、外围器件等待确认项。
6. 近似候选：违反约束及风险，与正式推荐隔离。
7. 待核实候选：缺失或冲突证据。
8. 证据不足与下一步。

默认使用中文回答，型号、参数符号、单位、引脚名和关键术语保留英文；证据区显示官方英文原文片段。

## 8. 功能边界

首版筛选和比较芯片，并在数据充分时执行可验证的基础计算。暂不自动生成最终电感、电容、补偿网络、PCB 布局或热设计结论。

推荐结果不能直接作为硬件定型或设计签核。任何进入原理图、BOM 或样机的型号必须由工程师复核并通过实际验证。

## 9. 应用架构

采用独立 Python 核心模块、本地 FastAPI 接口和 Streamlit 界面。开发期间先用命令行验证核心模块，再连接 API 与网页。

建议逻辑层次：

1. 原始文档与版本清单。
2. 文档解析、表格抽取和证据定位。
3. 人工审核的结构化产品库。
4. 需求解析与单位归一化。
5. 硬约束规则和基础计算。
6. 候选排序。
7. 关键词、向量和元数据混合检索。
8. 证据绑定与本地 LLM 解释。
9. FastAPI 与 Streamlit。
10. 评测、发布与回滚。

## 10. 隐私与安全

- 安装和资料准备阶段允许联网；部署完成后可断网运行。
- 程序只监听 `127.0.0.1`，不调用云端 API。
- 完成安装后阻断相关进程公网访问，并执行真实断网验收。
- 默认不持久化原始问题和完整回答。
- 持久化日志只记录时间、耗时、检索数量、错误类型和匿名指标。
- 失败案例只能由用户主动选择、查看并脱敏后保存。
- 所有导入资料均为不可信内容，不能覆盖系统规则、执行命令或访问网络。
- 首版只使用公开资料，可暂不强制磁盘加密。
- 导入内部资料前，必须确认 BitLocker、账户权限、备份位置与临时文件策略。
- 不自动同步网盘或云备份。

## 11. 版本管理

原始官方文件按哈希和版本归档，不直接覆盖。每次发布生成知识库版本号；新版完成解析、人工审核和回归测试后才能成为当前版本。旧版资料保留供追溯，但退出当前推荐索引。产品参数、证据和评测结果均记录所属版本，并支持回滚。

## 12. 首版验收标准

- 违反硬约束的型号进入正式推荐：0 次。
- 每条关键参数的出处可打开并定位：100%。
- 引用内容确实支持对应结论：至少 95%。
- 缺少最低输入字段时能追问而非正式推荐：100%。
- 正确证据进入候选集的 Recall@10：至少 95%。
- 无依据问题正确拒答或声明证据不足：至少 90%。
- 热启动完整推荐通常不超过 30 秒。
- 未通过人工审核的产品记录进入正式推荐：0 次。

首批建立约 30 条评测需求，覆盖：充分信息、缺失信息、无合格型号、近似候选、待核实候选、单位换算、相似料号、资料冲突与无依据问题。
